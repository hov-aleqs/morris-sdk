# Morris Ads для Unity

Обёртка над нативным Morris SDK. Реклама с вознаграждением и межстраничная в
Unity-играх под Android.

Это **мост**, а не второй SDK: показ, трекинг и вся логика живут в нативной
библиотеке, здесь только C#-поверхность и перекладывание вызовов.

## Подключение

```csharp
using Morris.Ads;

void Start()
{
    MorrisAds.Initialize("https://ads.example.com/api/ad");
}

void ShowRewarded()
{
    var ad = new MorrisRewardedAd("rewarded_main");
    ad.Loaded   += a => a.Show();
    ad.Rewarded += (a, reward) => GiveCoins(reward.Amount);
    ad.LoadFailed += (a, error) =>
    {
        // Отсутствие рекламы — обычный исход, а не сбой.
        if (!error.IsNoFill) Debug.LogWarning(error);
    };
    ad.Load();
}
```

`MorrisInterstitialAd` устроен так же, но без события о награде.

**Все события приходят в главном потоке Unity** — из обработчиков можно
свободно трогать сцену и интерфейс. Нативный SDK зовёт свои колбэки на главном
потоке Android, а это другой поток; мост перекладывает их сам.

Не забывайте `Destroy()`, когда юнит больше не нужен: после него события не
приходят.

## В редакторе

Реклама работает только на устройстве Android. В редакторе `Load()` сразу
завершается отказом с внятным текстом — это ожидаемо, а не поломка.
Проверяйте `MorrisAds.IsSupported`, если хотите развести пути явно.

## Виды ошибок

| `error.Kind` | что произошло |
|---|---|
| `no_fill` | рекламы сейчас нет. Норма, не сбой |
| `network` | сеть недоступна или таймаут |
| `server` | бэкенд ответил не 2xx, код в `error.HttpCode` |
| `malformed` | ответ пришёл, но показать его нельзя |

Разбирайте по `Kind`, а не по тексту: текст написан для человека и может
измениться.

## Установка

Пока SDK не опубликован в Maven, пакет берётся из этого репозитория, а
библиотека кладётся в него задачей сборки:

```bash
./gradlew :morris-sdk:syncUnityPlugin
```

Затем в Unity: **Window → Package Manager → + → Add package from disk** и выбрать
`unity/com.morris.ads/package.json`.

После публикации SDK в Maven здесь появится `Dependencies.xml` для EDM4U,
файл библиотеки уйдёт, и пакет станет ставиться по ссылке:

```
https://github.com/<org>/morris.git?path=/unity/com.morris.ads#v1.0.0
```

## Как мост не разъезжается с SDK

Вызовы в Kotlin идут по **строковым** именам через JNI — компилятор не проверяет
ни одного из них. Переименовали метод в SDK, и сборка остаётся зелёной, а у
игрока просто перестаёт приходить награда.

Поэтому сборка запускает сверку с настоящим AAR:

```bash
./gradlew :morris-sdk:checkUnityBridge
```

Она проверяет, что все классы и методы существуют, и сверяет слушателей в обе
стороны: не пропал ли колбэк из моста и не обрабатывает ли мост то, чего в SDK
уже нет.

Вторая проверка — компиляция самого C# **без Unity**:

```bash
./gradlew :morris-sdk:checkUnityCompile
```

Мост собирается против настоящей `UnityEngine.dll` (пакет NuGet от Unity
Technologies, 6 МБ вместо 4.4 ГБ редактора) в трёх видах: под устройство со
всем JNI-кодом, под редактор и под другую платформу. Нужен .NET SDK; без него
проверка честно сообщает, что пропущена.

Обе проверки входят в `./gradlew build` и роняют сборку при расхождении.

## Чего здесь нет

Файлов `.meta` — Unity создаст их сама при первом импорте. iOS — нативного SDK
под неё пока не существует, и обёртка накроет обе платформы, когда он появится.
